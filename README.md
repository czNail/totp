# TOTP 验证器

个人使用的轻量本地验证器。九宫格手势或 6 位 PIN 解锁，多账号实时动态码，浏览器本地加密保存；无后端、无注册、无分析脚本或运行时外部依赖。

目标地址：<https://cznail.github.io/totp/>。主页仓库只维护工具入口，本仓库独立开发和部署。

## 使用

1. 首次打开，设置并确认 6 位数字 PIN；已有账号继续使用原 PIN，无需重新添加。
2. 添加账号，粘贴 Base32 验证器密钥或 `otpauth://totp/…` 链接。链接会自动填写账号、服务和参数。
3. 点击验证码复制；倒计时结束后自动更新。支持 SHA-1 / SHA-256 / SHA-512、6 / 8 位和 1–300 秒周期。
4. 在「设置 → 设置手势密码」中，按住连接至少 4 个不同的点，连续绘制两次。启用后默认优先手势，PIN 同时可用，任意一种通过即可进入。支持鼠标、触屏、触控笔和数字键选点；跨过未选的中间点时会自动补齐，已选点不会重复。
5. 支持搜索、重命名、删除账号。使用期间保持解锁，点击锁定或刷新、关闭、离开页面后重新验证。可在设置中修改或关闭手势；修改 PIN 保留手势，修改手势保留 PIN。
6. 在「备份」中导出加密 JSON。备份包含账号及两种解锁方式，恢复时可使用备份当时的 PIN 或手势，会**替换**当前浏览器全部账号及解锁设置，确认后才执行。修改密码后请重新导出备份；旧文件仍使用旧密码。

清理站点数据、更换浏览器或隐私窗口关闭后，账号可能丢失。忘记手势可以切换 PIN 并重新设置；两种密码都忘记且没有能够解锁的备份时，只能清空本机数据重新开始。删除本地账号不会关闭服务端的两步验证。

页面加载完成后，断网仍能生成动态码；设备时间需准确。未实现 Service Worker，因此不保证断网时重新打开或刷新页面。不会从页面 URL 自动导入或接收密钥。不支持 HOTP、二维码扫描、云同步或系统认证。

## 本地保护

- 第 2 版格式使用随机 AES-256-GCM 数据密钥，将全部账号名称、服务、密钥、参数一起加密。PIN 和手势各用独立随机 16 字节盐，经 PBKDF2-SHA-256（600,000 次）派生不可导出的包装密钥，分别包装同一数据密钥。两种凭据都能真正解密账号库，不保存可用来绕过验证的明文密钥。
- 数据密钥在当前页面内存中可包装导出，以便增加或修改解锁方式；持久化内容只有包装后的密钥、账号密文和随机修订标识。PIN、手势、派生包装密钥及明文账号均不持久化。锁定和关闭弹窗时清理手势路径、敏感表单与会话引用；JavaScript 运行时不保证物理内存清零。
- 每次保存数据和包装密钥均使用新的随机 12 字节 IV、128 位 GCM 认证标签。数据附加认证信息绑定两种解锁配置，包装附加认证信息绑定格式、解锁类型和 KDF 参数。
- 第 1 版的账号库和 PIN 备份继续支持：首次成功用 PIN 解锁后，在事务修订检查通过时升级为第 2 版；升级保存失败时保留原库。新版备份需要当前或更新版本的工具恢复。
- 导出仅包含同一加密封装。恢复第 2 版备份时保留两种包装密钥并使用新的数据 IV；恢复第 1 版备份时生成新的数据密钥和 PIN 包装。修改某一凭据时重新生成其盐和包装 IV，另一凭据保持有效。旧备份保留导出时的密码及设置。
- 同一事务中比较修订号后写入，阻止旧标签页覆盖新数据；标签页之间仅广播变更通知，不广播账号或密钥。
- 备份格式、账号数量、密钥和算法均校验；文件限制 2 MB，最多 200 个账号。导入校验或保存失败时保留原库。
- CSP 限制页面网络连接，不加载第三方字体、脚本或统计。主题偏好使用主页共用的 `localStorage` 键 `neil-homepage:theme`，不涉及账号。

6 位 PIN 和九宫格手势均按体验优先提供基础保护：密文被复制后仍可能被离线枚举，PBKDF2 只增加成本；无法防御被控制的设备、扩展或页面脚本。独立仓库方便维护；GitHub Pages 上同一域名的不同路径仍属于同源。

## 开发与测试

需要 Node.js 24。

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

`npm run dev` 默认使用 Vite 的开发服务。生产 CSP 禁止网络连接，会阻止开发热更新的 WebSocket；常规页面刷新仍可用于调试。`npm run preview` 用于检查构建后的真实运行结果。

- `src/totp.ts`：Base32、otpauth 解析、HMAC 与动态码计算。
- `src/vault.ts`：双凭据密钥包装、AES-GCM、备份、旧格式升级和账号数据校验。
- `src/pattern.ts` / `src/pattern-pad.ts`：九宫格路径规则与 Pointer Events / 键盘交互。
- `src/storage.ts`：IndexedDB 与原子修订检查。
- `src/main.ts`：界面、会话、复制、备份恢复、跨标签页处理。
- `tests/`：RFC 6238 三种算法全部 18 组标准向量、RFC 4226、边界、解析与加密校验。
- `e2e/`：真实 Chromium 中验证账号流程、手势 / PIN 独立解锁、密码修改、双方式备份恢复、旧格式迁移、事务失败、触屏、键盘、离线、移动布局和锁定。

算法参考：[RFC 6238](https://www.rfc-editor.org/rfc/rfc6238)、[RFC 4226](https://www.rfc-editor.org/rfc/rfc4226)。加密使用浏览器原生 [Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API)。

## GitHub Pages

1. 在仓库 **Settings → Pages → Build and deployment**，将 **Source** 设置为 **GitHub Actions**。
2. 合并到 `main` 后自动运行单元测试、类型检查、构建和浏览器测试，再部署 `dist/`。也可手动执行工作流。
3. Vite 的 `base` 为 `/totp/`；部署地址以 Actions 实际返回值为准。
4. 发布验证成功后，在 `cznail.github.io` 的 `src/data/tools.json` 中登记 `/totp/` 入口。
